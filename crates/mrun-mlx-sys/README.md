# mrun-mlx-sys

Raw FFI bindings to [mlx-c](https://github.com/ml-explore/mlx-c) v0.7.0 over a statically
linked [MLX](https://github.com/ml-explore/mlx) v0.32.4, built from source. It is the engine
foundation of [mrun](https://github.com/hupe1980/mrun); the safe layer lives in `mrun-engine`
(feature `mlx`). The library name is `mlx_sys`.

Everything is `unsafe` and mirrors the C API one to one. The bindings (`src/bindings.rs`) are
generated by `regen.sh` and checked in, so building needs CMake and a C++ toolchain but no
libclang.

## What the build script does

- Fetches the mlx-c and MLX sources as GitHub archives of pinned commits, verified against the
  sha256 of the uncompressed tar (shallow `git fetch` as a fallback), and applies the patches in
  `patches/`.
- Builds both with CMake once per configuration (commits, patches, target, build type, Metal,
  SDK version, deployment target) and installs the result into the user cache, so every later build, profile,
  worktree and `cargo install` reuses it. The first build takes 3-40 minutes depending on the
  machine. OS file locks serialize concurrent builds.
- macOS: Metal backend plus CPU (Accelerate). `mlx.metallib` (the GPU kernels, ~215 MB) is
  exported to dependants as `DEP_MLXC_METALLIB`, and a zstd-compressed copy (~15 MB) as
  `DEP_MLXC_METALLIB_ZST`; `mrun-engine` embeds the compressed copy. For development builds the
  plain file is also copied next to the binaries in the target directory.
- Linux: CPU backend only, linked against OpenBLAS (with LAPACKE headers).

## Requirements

- CMake and a C++17 toolchain.
- macOS: Xcode with the Metal toolchain. The build compiles a one-line kernel to check it and
  stops with instructions when that fails:

  ```sh
  sudo xcode-select -s /Applications/Xcode.app
  xcodebuild -downloadComponent MetalToolchain
  ```

  `MLX_SYS_METAL=0` builds the CPU backend only (slow; tests and machines without Xcode).
- Linux: `cmake libopenblas-dev liblapacke-dev` (Debian/Ubuntu names).

## Environment variables

| Variable | Meaning |
|---|---|
| `MLX_SYS_CACHE_DIR` | Where builds and downloaded sources are kept. Default `~/Library/Caches/mrun-mlx-sys` (macOS), `$XDG_CACHE_HOME/mrun-mlx-sys` or `~/.cache/mrun-mlx-sys` (Linux). |
| `MLX_SYS_SOURCE_DIR` | Directory with `mlx-<commit>.tar[.gz]` and `mlx-c-<commit>.tar[.gz]` for offline builds; checked against the same hashes. |
| `MLX_SYS_PREBUILT_DIR` | Install prefix with `lib/libmlxc.a`, `lib/libmlx.a` (and `lib/mlx.metallib` on macOS) from an earlier build; skips fetching and CMake. |
| `MLX_SYS_METAL` | `1` requires Metal, `0` builds CPU only; unset on macOS means Metal. |
| `MLX_SYS_BUILD_TYPE` | CMake build type (default `Release`, also for debug cargo profiles). |
| `MLX_SYS_LINUX_LIBS` | Comma-separated system libraries on Linux (default `openblas`). |
| `MACOSX_DEPLOYMENT_TARGET` | The macOS version MLX is built for (unset: this Mac's); passed to CMake and part of the cache key, as is the SDK version. 26.2 or later with the 26.2 SDK compiles the M5 Neural Accelerator (`*_nax`) kernels. |
| `MLX_SYS_REQUIRE_NAX` | `1` fails the build when the deployment target is 26.2 or later but `mlx.metallib` holds no `*_nax` kernel; otherwise a warning. |

## Offline builds

The build downloads two source archives from GitHub (a few MB each). Without network access,
put them into a directory and point `MLX_SYS_SOURCE_DIR` at it:

```sh
mkdir -p ~/mlx-sources && cd ~/mlx-sources
curl -fLo mlx-36969c094354086e15d2a327a9c50feb20b9cf11.tar.gz \
  https://github.com/ml-explore/mlx/archive/36969c094354086e15d2a327a9c50feb20b9cf11.tar.gz
curl -fLo mlx-c-a341b4925024b88b2c593468f16e12f5e17315da.tar.gz \
  https://github.com/ml-explore/mlx-c/archive/a341b4925024b88b2c593468f16e12f5e17315da.tar.gz
MLX_SYS_SOURCE_DIR=~/mlx-sources cargo build
```

A populated `MLX_SYS_CACHE_DIR` (for example restored by a CI cache) needs no network either.

## docs.rs

With `DOCS_RS` set the build script builds nothing; the checked-in bindings are documented as
is.
