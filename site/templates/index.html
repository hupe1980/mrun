Built for the way agents work

Coding agents resend tens of thousands of tokens of instructions, tool schemas and history on every turn. On a laptop, re-reading that context dominates the wait. mrun is designed around that loop.

Exact prefix cache

The longest identical token prefix is reused across turns, subagents and edited history. Switching to a subagent moves the main conversation aside instead of throwing it away. Inside a tool loop the model's own reply is spliced back as the exact tokens it generated, so tool loops always hit.

Every miss explained

Each response reports cached and processed tokens. When reuse breaks, mrun names the cause (new, diverged, evicted, gap, disabled) and the message where the prompt changed, so you can fix it.

Predictable memory

Weights, sequence state, cache and scratch are budgeted at startup against unified memory, or set by the context you need (--context 64K). Requests that cannot fit are refused up front with the numbers. Under memory pressure, mrun sheds cache first.

Fast interruption

Cancellation is checked after every model layer and every token, and the prompt chunks already processed are kept for the retry.

Three APIs, one binary

OpenAI Chat Completions, Anthropic Messages and OpenAI Responses with streaming, tool calls and structured output — the protocols Claude Code, Codex and OpenCode actually speak.

Private by default

Loopback only, no telemetry, no prompt logging, offline after mrun pull. A model too big for your Mac can run across your Macs or on a rented GPU: opt-in, and the window says where prompts go.

How it works

  1. Your agent sends the whole conversation over one of three standard APIs.
  2. mrun renders and tokenizes it with the model's own chat template.
  3. The prefix cache finds the longest identical token prefix and moves its state back in — or simply continues the live conversation.
  4. Only the new tokens are processed on the Apple GPU, with nuvec's Metal kernels, in chunks that can be interrupted.
  5. Replies that copy decode faster: tokens drafted from the prompt are checked several at a time and kept only where the model would have written them.
  6. Tokens stream back with exact usage numbers and a cache report.
