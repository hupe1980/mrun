mrun runs open coding models — Qwen3.6, Qwen3-Coder and gpt-oss in the first release — on your Mac and serves Claude Code, Codex and OpenCode. It reuses attention state exactly across turns, branches and tool calls, explains every cache miss, and is designed to keep your Mac out of swap.

Built for the way agents work

Coding agents resend tens of thousands of tokens of instructions, tool schemas and history on every turn. On a laptop, re-reading that context dominates the wait. mrun is designed around that loop.

Exact prefix cache

The longest identical token prefix is reused across turns, subagents and edited history. Switching to a subagent moves the main conversation aside instead of throwing it away. Reuse is token-exact and bound to the model's content hash.

Every miss explained

Each response reports cached and processed tokens. When reuse breaks, mrun names the cause, the position where the prompt diverged and the message it falls in — a changed tool list, an edited message, an evicted branch — so you can fix it.

Predictable memory

Weights, attention state and scratch space are budgeted at startup against unified memory. Requests that cannot fit are refused up front with the numbers. Pressure sheds cache, never your editor.

Fast interruption

Cancellation is checked after every model layer and every token, designed so an interrupted request stops within one model layer, and the work already done is kept for the retry.

Three APIs, one binary

OpenAI Chat Completions, Anthropic Messages and OpenAI Responses with streaming, tool calls and structured output — the protocols Claude Code, Codex and OpenCode actually speak.

Private by default

Loopback only, no telemetry, no prompt logging, offline after mrun pull. Tools run in your agent, never in the server.

How it works

  1. Your agent sends the whole conversation over one of three standard APIs.
  2. mrun renders and tokenizes it with the model's own chat template.
  3. The prefix cache finds the longest identical token prefix and moves its state back in — or simply continues the live conversation.
  4. Only the new tokens are processed on the GPU with Apple's MLX, in chunks that can be interrupted.
  5. Tokens stream back with exact usage numbers and a cache report.
