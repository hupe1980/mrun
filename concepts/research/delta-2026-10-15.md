## 1. MLX, mlx-c, mlx-lm

- **No release after v0.32.4, v0.7.0 or `ba8a08f`** [V `git ls-remote`, 2026-10-15]. The MLX `main`
  HEAD is the v0.32.4 tag commit. The fact check already lists the relevant v0.32.4 fixes.
- These September items are not cited elsewhere but are already inside the pin (v0.32.3 or earlier)
  [V `git merge-base`]:
  - #3912 fixes fp-quantized matmul corruption when the quantized dimension is not a multiple of
    32. This touches the MXFP4 path for gpt-oss-20b.
  - #4185 adds `force_fused` to SDPA.
  - #4431 fixes the K/V batch offset in `sdpa_vector_2pass_1_gqa`. This matters for GQA decode.
  - #4211 splits the residency set.
  - #3872 adds zero-copy `mx.array(host_buffer, copy=False)`.
- **Still missing**: quantized-KV SDPA (issue #3404 open [U]). The 002/003 assumption "Q8 KV needs
  `quantized_matmul` at decode" stands.
- Reference point: Splash avoids MLX entirely. It uses hand-written Metal kernels per model shape,
  with weights repacked at load.

## 2. Clients

### 2.1 Claude Code (2.1.293 to 2.1.300, 2026-10-07 to 10-14) [V CHANGELOG]

- **Idle compaction** (2.1.299): compacts a conversation of 200K+ tokens idle for about 54 min. Two
  controls: `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`, or `"idleCompaction": false` in settings.json.
  → Finding #3.
- **Stream abort at 180 s** behind a custom `ANTHROPIC_BASE_URL` when feature flags were not loaded;
  fixed in 2.1.299, so it now waits 300 s. → Finding #4.
- A gateway-specific model name behind a custom base URL ended with "Prompt is too long · automatic
  compaction failed" near 200K (fixed in 2.1.299). mrun's launcher already sets
  `CLAUDE_CODE_MAX_CONTEXT_TOKENS`, but versions before 2.1.299 can misbehave near 200K.
- `ENABLE_TOOL_SEARCH=auto` turned itself off mid-conversation after MCP reconnects (fixed in
  2.1.300). Without the fix, the tools region changes mid-session and every request after it
  misses the cache.
- Tool-search-loaded MCP descriptions are now cut at 16,384 characters instead of 2,048. Expanded
  `tool_reference` blocks get larger (002 FR-028 rendering).
- Replies cut at the output limit no longer end the turn silently after a fallback to non-streaming.
  `count_tokens` was fixed for adaptive-thinking-only models behind gateways.
- `autoCompactWindow` is now accepted in subagent frontmatter, so subagents may compact at a
  different window than the main thread. 003 SC-002 assumes subagent prefixes are stable [I].
- Not applicable to mrun: Claude apps gateway features, MCP protocol 2026-07-28 negotiation (client
  to MCP server), and `/advisor`.

### 2.2 Codex (rust-v0.162.1 2026-10-09; main `bb64b89` 10-15; npm alpha 0.163.0-alpha.11) [V]

- `bc9cad34`: `response.incomplete` becomes a terminal `ResponseIncomplete`. `816fa702` records
  usage from incomplete responses. → Finding #2.
- `c6049ebd` (10-02): `model_providers.<id>.capabilities.{external_web_access, remote_compaction}`.
  Remote compaction defaults to `unsupported` for non-OpenAI, non-Azure providers, so it is still
  local for mrun.
- `669449b0`, `1a69ad32`, `9e03960c` (10-13): `async_compaction` (off by default) launches background
  compaction. It is only "speculative remote V2 compaction", so it is irrelevant unless a provider
  claims `remote_compaction = "v2"`. mrun must not claim it.
- `fd75aa11`: the namespace capability gate is removed, so namespaces are always sent. This confirms
  002 FR-027. Tool search stays gated on `supports_search_tool`.
- `6326163b`, `402f5b6f`: incremental tool-catalog deltas apply **only to "Responses Lite"** (an
  internal OpenAI transport). Standard Responses keeps the full tool list, so there is no change
  for mrun.
- `44dd77b7`: `Retry-After` inside `response.failed` `error.headers` is honored. mrun's queue-full
  errors (002 FR-010) could carry it [I].
- `c9253c49` (base instructions as a `developer` input item) was already reflected in 002 research
  line 161.

### 2.3 OpenCode (v2.0.29 2026-10-14; dev `bdf4793`; npm `opencode-ai` still 1.19.0) [V]

- `a3f7f42a`: after `finish: length` it appends "Your last response hit the output token limit…"
  and continues; it fails after two continuations. This prefix-appends, so it is cache-friendly.
- `c9e1ed70`: malformed tool arguments are rejected and unfinished calls settled. This matches
  002 FR-004 (never report a truncated call as complete).
- `39105835`: a shared local discovery plugin for vLLM (`:8000`, `owned_by == "vllm"`), LM Studio
  and Ollama.
- `460c626a`: the Bun 5-minute fetch idle timeout is gone. Builds before 10-12 abort after 5 min of
  silence, so FR-026 keepalives cover this.
- `69a71426`: `compatibility.cacheFormat` for Anthropic cache breakpoints. mrun ignores
  `cache_control` (002 FR-030), so this needs nothing.

## 3. Competitors

### 3.1 Inco Splash (github.com/incoai/splash, Apache-2.0)

- **Releases**: 1.0 on 2026-09-18, 1.3.2 on 2026-10-14 [V tags].
- **Stack**: C++/Objective-C++ with hand-written Metal kernels, plus a Python HTTP server
  (`server/`). It does not use MLX [V tree]. It needs **M3+ and macOS 26.4+**; an unofficial
  M1/M2 port exists (paperniuk/splash) [U].
- **Models**: two families only, Qwen3.8-27B and Qwen3.6-35B-A3B. It loads Unsloth GGUF and
  `mlx-community/*-4bit` (also mxfp4 and nvfp4), each with a matching trained **DFlash2** draft
  (Inco blog only, no paper) [V README; U blog].
- **Features** [V DEVELOPMENT.md]:
  - Chat, Responses (stateful store, 64 MiB LRU, `previous_response_id`), Completions and
    Messages; namespaces flattened to `ns__name`; hosted search refused.
  - Tool parser ends values only at `\n</parameter>\n` plus the next tag, like 002 FR-004. Unlike
    mrun, it coerces types (`True` becomes `true`, strings to numbers).
  - **Default INT8 KV and FP32 GDN state.** Arithmetic depends on batch and chunking; the docs say
    so.
  - Replay point at the last 32-token page before the generation prompt; rolling checkpoints every
    4,096 tokens.
  - SSD tier (auto, ≤ 32 GiB) and `--persistent-cache`: a namespace digest of manifests, layouts
    and format; the newest restore point ≥ 2,048 tokens deep is written 10 s after publication.
  - A memory governor driven by macOS pressure levels. Priority suspension. Requests wait for a
    prefix another lane is computing.
  - ANE W8A8 FFN split for dense prefill.
  - **Unloads after 10 min idle by default** (`--idle-release`).
  - `/v1/systemone`.
  - Launchers set `ANTHROPIC_*` model slots, `CLAUDE_CODE_MAX_CONTEXT_TOKENS` and
    `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, and Codex `model_context_window` with the auto-compact limit
    at 90% (`install/clients.py:173-298`).
- **Vendor performance** (Splash 1.0 on an M5 Pro, 16-core GPU, 48 GB) [U]:

  | Metric | Qwen3.6-35B-A3B | Qwen3.8-27B |
  |---|---|---|
  | Decode | 210 tok/s (1.7× the next engine) | 74 tok/s |
  | Prefill at 32K | 2,011 tok/s | 363 tok/s |
  | Cached TTFT, 32K replay | 123 ms | 282 ms |

  On GGUF against llama.cpp, decode is 2.5–3.2× (35B) and 4.5–5.3× (27B). Top-1 agreement with
  llama.cpp is 97.8–99.5%. The comparison set was oMLX, Lily, uzu and Ollama.
- **Ecosystem**: LM Studio 0.4.25 (2026-09-19) offers Splash as an experimental backend [U changelog
  via search], and oMLX issue #4132 asks to serve through it [U].
- **For mrun** [I]:
  - **Splash already occupies the "fast default-model agent server" slot on M3+.**
  - mrun's remaining differences:
    - bf16 KV by default, with bit-exact cache-on = cache-off as a gate (003 SC-005);
    - no idle unload;
    - Rust single binary, no Python;
    - five families on MLX, including M1/M2;
    - explained misses.
  - Splash with `--kv-format bf16` running alone is also deterministic, so "exact" must be claimed
    as a gate and a default, not as a unique capability.
  - Its decode lead comes mostly from DFlash2 drafts plus per-shape kernels. 006's n-gram-only
    scope will not close a 1.7–2× decode gap. Re-open trained drafters once the license and
    availability of the DFlash2 weights are checked [U].

### 3.2 llama.cpp (b11633+, HEAD `e467e5b` 2026-10-15) [V]

- `1fb7ef3` (10-02): the drafter samples probabilistically and the target verifies by rejection
  sampling (greedy by default; masks renormalized for grammar). This matches the arxiv-sota
  correction. `8330e96`: n-gram drafts were rejected at temp > 0 after truncation.
- `e467e5b` (10-15): plain KV caches ignored `PARTIAL_ONLY`, so every checkpoint copied the whole
  MTP or draft KV and grew per token.
- `2639a3b`: only restorable states are saved to the RAM prompt cache.
- `23b0202`: a busy slot was loaded from the RAM cache while still generating, so generation
  continued on the wrong context.
- `2232bc8`: Metal MXFP4 mul-mat uses bf16 math (gpt-oss). `073b740`: Metal `mul_mat_id` with
  duplicate ids.
- `a4cb4c6`: `/v1/systemone` decision API; models laya, julia-1, lev, openjev and kev.
- `4d60b4d`: `GET /models` reports `architecture.input_modalities/output_modalities`.
